# THE GIT SHITTER — REPO SEED NURSERY

**Status: experimental Git branch, not live source repos.**

This nursery revives Merry's historical `repo_seed.txt` method (see `chromostereopsis`, `metamerism`, `gyroid_lattice`, and `cuttlefish_chromatics`).

A seed is a detailed specification that can grow into an independent repo. It is **not** a generic prompt, and it is not a claim that an app already works. Each seed must give an agent actual math/style principles, plausible algorithms, code or pseudocode, parameters, modular interfaces, export formats, example presets, links to existing sibling repos, failure cases, and an ordered build directive.

## Rules of the nursery
1. Do not alter Merry's existing labs, Git Shitter's active `config.json`, scheduled generator, or the `monetize` factory.
2. Crossbreed math with style by assigning each parent a *causal role* (geometry, behavior, optical finish, etc.), not just blending adjectives.
3. Seed the *science* accurately and label fantasy extrapolations as inventions.
4. Prefer browser/JS/SVG/Canvas/shaders and deterministic parameters to API calls.
5. Make every idea testable: a small runnable renderer or SVG export is a higher milestone than a gorgeous mockup.
6. A source repo is created separately when approved; these seed files are staging briefs until then.
7. Personal source labs are separate from later commercial forks. `monetize` handles packaging downstream.
8. Check sibling repos before implementing duplicate mathematics, styles, utilities, or renderers.
